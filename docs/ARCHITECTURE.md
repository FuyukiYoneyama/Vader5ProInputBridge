# 構成と通信仕様

## 入力と出力

```text
VADER 5 PRO 拡張HID MI_01
  → HidConnection：受信・取得要求・再接続
  → BridgeEngine：順番に処理・入力値・姿勢計算
      ├→ VJoyStandardOutput：vJoy 1の通常入力と追加ボタン
      └→ OpenTrackOutput：UDPの姿勢送信

WindowsのvJoy 1 → DInput Reader 1：独立した読戻し
Windowsの標準入力 → XInput Reader：独立した診断
```

HID（機器の入力・制御用インターフェース）の受信と処理は背景で実行し、受信順のレポート（入力データ一式）を処理する。画面は固定した数値とランプを更新する。ファイル記録は明示的にONにした区間で実行する。

## 入力の形式

対象の既定識別値はVID（メーカー番号）`0x37D7`、PID（製品番号）`0x2401`。機器のパスは起動・再接続時に列挙する。解析は先頭にレポートID（入力形式の番号）がある形と、省かれた形に対応する。

ヘッダー`5A A5`とコマンド`EF`を正常入力として識別する。以下の位置は`5A`を0として数える。

| 位置 | 内容 |
|---|---|
| 3/5/7/9 | LX/LY/RX/RY：符号付き16ビット |
| 11/12/13/14 | 通常・追加ボタンと十字キーのビット |
| 15/16 | LT/RT：符号なし8ビット |
| 17/19/21 | ジャイロのセンサー値 |
| 23/25/27 | 加速度のセンサー値 |

16ビットはリトルエンディアン（下位バイトを先に並べる形式）。Gyro X/Y/Zは位置17/21/19の順で、最後の軸を反転する。加速度X/Y/Zは位置23/27/25の順で、最後の軸を反転する。

- ジャイロの換算：`raw / 32768 × 2000 × π / 180`、単位rad/s（ラジアン毎秒）。
- 加速度の換算：`raw × 9.80665 / 4096`、単位m/s²。
- ボタンのビットと物理ボタンの対応は`VaderReportDecoder.cs`、出力番号は`config/bridge.json`の`standard.buttons`。

解析と要求形式の参照元は[第三者の著作権表示](../THIRD_PARTY_NOTICES.md)に記載する。

## 取得と回復

取得要求はコマンド`1C`、機器情報要求は`01`。取得／解除の要求には機器側の仕様に合わせた`SDL`の識別文字列を含める。送信方式の既定値はWriteFile（Windowsのデータ書込み関数）で、診断時にHidD_SetOutputReport（HID用の出力関数）を選べる。

接続・受信・処理・出力の状態を分けて記録する。読取りの停止と回復中は出力の最終値を保持し、列挙と取得を再試行する。設定通信の待機と正常入力の再開を別々に扱う。通常終了は要求の解除、休止値の出力、ハンドル（機器を開いている資源）の解放を実行する。

## 姿勢とOpenTrack

Yaw（左右へ向きを変える回転）はGyro Yの角速度を度毎秒へ換算して偏差を差し引き、実測のdt（前の測定からの経過秒数）を掛けて積算する。初回は約2秒・200件以上の静止サンプル（時刻ごとの測定値）からバイアス（静止時のゼロ点偏差）を決める。

Pitch（前後の傾き）とRoll（左右の傾き）はジャイロと重力方向を組み合わせる。HOME短押しの解放で正面を更新する。通信途絶後は保持した角度から時刻の計算を再開する。

OpenTrackへのUDP（アプリ間でデータを送る通信方式）は、64ビット浮動小数点6個・48バイト。X/Y/Z/Yaw/Pitch/Rollの順で、位置の3値は0、回転は度。既定の宛先は同じPCの`127.0.0.1:4242`。送信時計とソケット（通信の資源）は入力と独立して管理する。

## 記録の意味

受信・処理・解析・vJoy書込みの件数を個別に表示する。Bridgeの書込み値は出力要求の結果で、DInput ReaderはWindows側の読戻しを示す。OpenTrackの送信件数と、OpenTrack側の受信表示も個別の確認点として扱う。
